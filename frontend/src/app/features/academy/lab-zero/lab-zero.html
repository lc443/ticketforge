What can go wrong

A forgotten AWS resource keeps running.

A leaked credential, NAT gateway, database, or resource in the wrong Region can remain active after you close the terminal.

What you will do

Check before creation and verify after deletion.

Exercise 1 · root boundary

Protect the master identity

Never enter a root password, MFA code, access-key ID, or secret access key into TicketForge Academy.

AWS Console
→ Sign in as root only for root-required setup
→ Account → Security credentials
→ Register at least one MFA method
→ Confirm no root access keys exist
→ Sign out of root
root user

Has unrestricted account authority. It is reserved for tasks that require root rather than normal administration.

MFA

Adds a possession or phishing-resistant factor so a password alone cannot authorize root access.

no access keys

Long-lived root API keys create unnecessary, extremely privileged credential risk.

Exercise 2 · daily identity

Create a named administrative access path

AWS Console
→ IAM Identity Center
→ Enable
→ Create a named user
→ Assign the minimum permission set needed for setup
→ Sign in through the AWS access portal
Identity Center

Centralizes workforce sign-in and issues temporary role credentials rather than permanent root credentials.

permission set

Defines which role permissions the identity receives in an AWS account.

least privilege

Begin with only required actions, then narrow broad setup permissions as the lab environment matures.

Exercise 3 · CLI identity

Prove which account and role will receive commands

aws configure sso --profile ticketforge-lab
aws sso login --profile ticketforge-lab

aws sts get-caller-identity \
  --profile ticketforge-lab

aws configure get region \
  --profile ticketforge-lab
--profile

Selects the named local credential configuration explicitly instead of relying on an unknown default.

sts get-caller-identity

Returns non-secret account, principal ARN, and user ID evidence for the active credentials.

region

Defines the default regional destination. Global and regional services still have different scopes.

Exercise 4 · cost controls

Configure thresholds and unusual-spend detection

Billing and Cost Management
→ Budgets → Create a small monthly cost budget + email alerts
→ Cost Explorer → Enable if required
→ Cost Anomaly Detection → Create monitor + alert subscription
→ Confirm the notification email
Budget

Compares actual or forecast spending with thresholds you define and sends notifications.

Cost Anomaly Detection

Looks for spend patterns that are unusual relative to expected behavior.

alert, not brake

These controls notify; they do not guarantee that resource creation or charges stop.

Exercise 6 · teardown invariant

Make cleanup part of every future lab

# Before a lab: prove caller and Region.

# After a lab: query the service, tags, and every Region used.
# The exact deletion and absence checks belong to that service's lab.
create inventory

Record every resource and dependency as it is created, including resources a service creates on your behalf.

dependency order

Delete consumers before providers when AWS enforces references—for example, detach before deleting a network.

absence evidence

A successful delete command is not enough; query again and prove the resource no longer exists.
