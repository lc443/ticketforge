Sprint 22

Helm release packaging

Package Kubernetes application intent, validate environment contracts, and rehearse safe upgrade and rollback.

The problem

Copied YAML drifts and loses release history.

Hand-edited development and production manifests can silently diverge. Operators need validation, ownership, repeatable upgrades, and a known recovery path.

The solution

Package the stateless application plane as a versioned release.

Templates define stable structure, values define environment policy, schema rejects invalid configuration, and Helm records an auditable release history.

Exercise 1 · package boundary

Read the chart contract before rendering it

Chart.yaml

Identifies the package and versions the chart separately from the application.

values.yaml

Contains safe development defaults; it is configuration input, not another template.

boundary

The chart owns API/frontend application resources. Data services, controllers, Secrets, and certificate issuance remain platform concerns.

Exercise 3 · environment rendering

Compare policy without copying templates

helm template ticketforge-dev infrastructure/helm/ticketforge \
  > /tmp/ticketforge-dev.yaml

helm template ticketforge-prod infrastructure/helm/ticketforge \
  --values infrastructure/helm/ticketforge/values-production.yaml \
  > /tmp/ticketforge-prod.yaml

kubectl apply --dry-run=server --filename /tmp/ticketforge-dev.yaml
kubectl apply --dry-run=server --filename /tmp/ticketforge-prod.yaml
--values

Overlays production policy such as replica bounds, images, hostname, and TLS onto one template set.

helm template

Renders locally without creating a release, making output reviewable in CI.

--dry-run=server

Asks the live API server to validate resource schemas and admission without persisting them.

Exercise 4 · release lifecycle

Install and upgrade atomically

kubectl create namespace ticketforge-helm-test

helm upgrade --install ticketforge-chart-test \
  infrastructure/helm/ticketforge \
  --namespace ticketforge-helm-test \
  --set fullnameOverride=ticketforge-test \
  --set api.enabled=false \
  --set frontend.replicaCount=1 \
  --set gateway.enabled=false \
  --wait --atomic --timeout=180s

helm status ticketforge-chart-test --namespace ticketforge-helm-test
upgrade --install

Creates a missing release or reconciles an existing one, giving automation one idempotent command.

--wait

Waits for workloads to become ready instead of reporting success immediately after submission.

--atomic

Deletes a failed install or rolls back a failed upgrade, bounded by the timeout.

Exercise 5 · release test

Test through the declared network boundary

helm test ticketforge-chart-test \
  --namespace ticketforge-helm-test \
  --logs --timeout=120s

kubectl get networkpolicy --namespace ticketforge-helm-test
helm.sh/hook: test

Creates an ephemeral Pod that checks the frontend Service after deployment.

--logs

Returns test output with the release result; TicketForge prints healthy.

least privilege

Default-deny remains enabled; one narrow policy allows only labelled chart-test Pods to the frontend port.

Exercise 6 · recovery

Inspect history, roll back, and clean up

helm history ticketforge-chart-test --namespace ticketforge-helm-test
helm rollback ticketforge-chart-test 1 \
  --namespace ticketforge-helm-test \
  --wait --timeout=180s

helm uninstall ticketforge-chart-test --namespace ticketforge-helm-test
kubectl delete namespace ticketforge-helm-test
history

Shows numbered revisions and whether each install, upgrade, or rollback succeeded.

rollback

Creates a new revision from an earlier chart state; it does not reverse database migrations or external side effects.

uninstall

Deletes release-owned resources. The disposable namespace prevents collisions with the Kustomize-managed development stack.
