Sprint 24

Terraform state and recovery

Move infrastructure identity into a shared, locked, versioned backend and rehearse the failure paths that make state an operational system.

The problem

A local file cannot coordinate a delivery team.

A second engineer may recreate an existing resource, two pipelines may overwrite state, and a lost laptop may erase the only ownership map.

The solution

Centralize identity, serialize writers, preserve history.

TicketForge uses an S3-compatible backend with a native lockfile, versioning, encryption, and a rehearsed import, drift, contention, and recovery workflow.

Exercise 1 · backend bootstrap

Build the registry before storing its own record

docker compose \
  --file infrastructure/terraform/state-lab/backend/docker-compose.yml \
  up --detach --wait

AWS_ACCESS_KEY_ID=test AWS_SECRET_ACCESS_KEY=test \
aws --endpoint-url http://localhost:4566 \
  s3api get-bucket-versioning \
  --bucket ticketforge-terraform-state
bootstrap

The backend must exist before Terraform can initialize against it. Production commonly uses a separate foundation stack or account.

--wait

Returns only after the health check succeeds, preventing initialization against a container that is running but not ready.

versioning

Preserves prior object versions so a completed bad state write has a recovery path.

Exercise 2 · initialization

Attach Terraform to shared state without committing credentials

export AWS_ACCESS_KEY_ID=test
export AWS_SECRET_ACCESS_KEY=test
export AWS_DEFAULT_REGION=us-east-1

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  init -backend-config=backend.local.hcl

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  state list
backend.local.hcl

Supplies non-secret backend settings to a partial backend declaration. Credentials stay in environment variables.

init

Connects the working directory to the remote state key and installs the pinned providers.

state list

Lists addresses Terraform already owns. An empty list means no identities are mapped yet—not that reality is empty.

Exercise 3 · adoption

Import an existing namespace without recreating it

kubectl create namespace ticketforge-import-lab

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root plan

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  import kubernetes_namespace.import_lab ticketforge-import-lab

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  state show kubernetes_namespace.import_lab
import ADDRESS ID

Binds the configuration address to an existing provider identity; it does not create the namespace.

before import

Terraform proposes creation because configuration exists but state has no identity mapping.

after import

The next plan reconciles declared attributes, such as labels, without replacing the adopted object.

Exercise 4 · drift

Choose whether intent or reality should win

# Deliberately edit generated/state-lab.json, then compare:
./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  plan -refresh-only

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  plan -out=repair-drift.tfplan

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  apply repair-drift.tfplan
drift

Reality changed outside Terraform, so configuration, state, and the observed object no longer agree.

-refresh-only

Shows how state would be updated to accept observed reality. Applying it is a governance decision, not a repair.

normal plan

Proposes changing reality back to declared intent. TicketForge used this path and then proved a no-op plan.

Exercise 5 · contention

Reject a second writer while an apply owns the lock

# Terminal A: deliberately hold the lock for 20 seconds.
./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  apply -auto-approve \
  -var=lock_drill_nonce=contention \
  -var=lock_hold_seconds=20

# Terminal B: expect "Error acquiring the state lock".
./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  plan -lock-timeout=3s
use_lockfile = true

Uses conditional S3 object creation so only one writer can own the state lock.

-lock-timeout=3s

Waits briefly for the owner, then fails safely instead of hanging or writing concurrently.

-lock=false

Disables protection and is not part of this workflow. Never use it to bypass a legitimate writer.

Exercise 6 · recovery

Locate the recovery point before an emergency

AWS_ACCESS_KEY_ID=test AWS_SECRET_ACCESS_KEY=test \
aws --endpoint-url http://localhost:4566 \
  s3api list-object-versions \
  --bucket ticketforge-terraform-state \
  --prefix ticketforge/state-lab/terraform.tfstate

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  state pull
VersionId

Identifies an immutable historical state object. Record the selected ID and justify it before recovery.

state pull

Reads the current remote state for protected backup or diagnosis; state can contain sensitive values.

restore

Recovery is followed by refresh and plan. Restoring bytes alone does not prove infrastructure and state agree.

Exercise 7 · controlled teardown

Destroy managed resources before deleting their registry

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  plan -destroy \
  -var=lock_drill_nonce=contention \
  -var=lock_hold_seconds=20

./.tools/terraform \
  -chdir=infrastructure/terraform/state-lab/root \
  destroy \
  -var=lock_drill_nonce=contention \
  -var=lock_hold_seconds=20

docker compose \
  --file infrastructure/terraform/state-lab/backend/docker-compose.yml \
  down --volumes
plan -destroy

Shows the ownership blast radius before deletion authority is granted.

destroy first

Keeps the ownership registry available while Terraform removes the resources it tracks.

down --volumes

Deletes this disposable local backend and every state version. Never equate this lab cleanup with a production backend deletion.
