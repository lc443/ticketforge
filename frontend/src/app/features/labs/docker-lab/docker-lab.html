Sprint 15

Docker: build once, run the same artifact

Turn TicketForge from a machine-dependent project into reproducible, disposable deployment units.

The problem

“It runs on my machine” is not a deployment strategy.

Host-built JARs, duplicated replica images, missing health gates, and container-local database files make releases inconsistent and fragile.

The solution

Build immutable images and externalize state.

Multi-stage builds compile in Docker, three APIs share one digest, health checks order startup, and PostgreSQL data lives in a named volume.

Core model

Image ≠ container

Image

Read-only recipe and filesystem. Built once and identified by a digest.

Container

A running instance of that image with a small writable layer.

Volume

State with a lifecycle independent of a disposable container.
