Authentication & Authorization Lab

Log in, inspect the token, then try to break it.

The problem

Sessions don't scale horizontally for free.

A server-side session lives in one instance's memory. Sprint 4 puts N API instances behind a load balancer — the instance that handles request #2 might not be the one that handled the login.

The solution

A signed token the client carries.

Login returns a JWT. Every later request sends it in the Authorization header. Any instance can verify the signature and read the role — no shared session store required.

Why it works
  • Stateless. No server-side session to keep in sync across instances.
  • Self-contained. Role and identity travel with the token.
  • Signature-verified. The client can read a token but can't forge one.
