Horizontal Scaling Lab

Kill an instance mid-traffic. Watch the load balancer route around it.

The problem

One API instance is a single point of failure.

It also caps throughput at whatever that one box can handle.

The solution

N identical, disposable instances behind NGINX.

Round-robin traffic across them. Health checks pull dead ones out of rotation.

Why it works
  • No single point of failure. One instance dying doesn't take the app down.
  • Elastic capacity. Add instances under load, remove them when it's quiet.
  • Requires statelessness — any instance must be able to handle any request.

Invariant

Any healthy replica must handle any request. Authentication, inventory, cache policy, and rate-limit state cannot depend on one JVM’s memory.

Failure clue

The first request that encounters a dead peer can be slower because passive NGINX failure detection needs an attempted connection before retrying another upstream.

  1. Start with one API and record availability and throughput.
  2. Add a second identical replica behind NGINX.
  3. Prove both use the same image digest.
  4. Stop one during traffic and explain every observed status and latency change.
