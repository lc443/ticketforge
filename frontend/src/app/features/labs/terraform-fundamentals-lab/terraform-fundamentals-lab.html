Sprint 23

Terraform fundamentals

Translate infrastructure intent into validated configuration, review a plan, and prove a complete resource lifecycle.

The problem

Runbooks describe actions, not durable intent.

Manual commands create snowflakes, hide ownership, and make reviewers guess what an infrastructure change will do.

The solution

Declare intent and review the execution plan.

Terraform combines typed inputs, provider resources, dependencies, state, and outputs so creation, change, and destruction follow one reviewable lifecycle.

Exercise 1 · toolchain

Verify the execution boundary

./.tools/terraform version
./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  init
-chdir

Changes Terraform's working directory before it loads configuration and state.

init

Initializes the backend and installs providers; it does not create managed resources.

.terraform.lock.hcl

Commits exact provider selections and checksums so collaborators resolve the same dependencies.

Exercise 2 · configuration language

Trace inputs through the dependency graph

data "local_file" "helm_chart" {
  filename = "${path.module}/../../helm/ticketforge/Chart.yaml"
}

resource "local_file" "environment_catalog" {
  filename = "${path.module}/generated/${var.environment}/environment.json"
  content  = jsonencode(local.environment_catalog)
}
data

Reads something that already exists; it does not claim lifecycle ownership of the Helm chart.

resource

Declares an object Terraform creates, observes, updates, and destroys.

references

Expressions form dependency edges; Terraform derives ordering instead of relying on filename order.

Exercise 3 · quality gates

Format, validate, and reject unsafe input

./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \

./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \

# Expected failure: below the two-replica availability floor.
./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  plan -var=api_replicas=1
fmt -check

Checks canonical HCL formatting without rewriting files.

validate

Checks configuration structure and provider schemas without proposing infrastructure changes.

validation

Moves architecture constraints into executable input contracts with useful errors.

Exercise 4 · reviewed change

Save a plan and apply exactly that plan

./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  plan -out=tfplan

./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  apply tfplan

./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  output
plan -out

Saves the reviewed execution plan instead of recalculating actions during apply.

apply tfplan

Executes the saved proposal and records resulting resource identity in state.

output

Publishes stable values for people, pipelines, or another Terraform configuration.

Exercise 5 · change semantics

Compare no-op, update, and replacement

# Same desired state: expect "No changes."
./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals plan

# Valid capacity change: inspect before applying.
./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  plan -var=api_replicas=4
no-op

Proves idempotence: declared intent, state, and observed reality agree.

~

An in-place update preserves resource identity while changing attributes.

-/+

Replacement destroys and recreates identity; production plans require blast-radius review.

Exercise 6 · controlled teardown

Review destruction before approving it

./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  plan -destroy

./.tools/terraform \
  -chdir=infrastructure/terraform/fundamentals \
  destroy
plan -destroy

Previews deletions before authority is granted; inspect exact addresses and counts.

destroy

Removes resources tracked by this state, not arbitrary files or infrastructure.

state

Connects resource addresses to real identity. Sprint 24 examines why local state is unsafe for team coordination.
